5. JOB HUNTER — PROJECT SNAPSHOT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Side build for a friend seeking a PM role. Automated daily job application
web app. Mission: maximize interview callbacks via volume (10/day) + quality
(customized materials + direct hiring manager contact).

DAILY PIPELINE (runs 8:00 AM):
  1. SCRAPE   → LinkedIn, Indeed, Glassdoor, Google, ZipRecruiter, Craigslist
  2. SELECT   → score by relevance, dedupe vs log, pick top 10
  3. ENRICH   → LLM tailors resume + cover letter per JD
  4. CONTACT  → DuckDuckGo → email permutation → SMTP verify (free, no API)
  5. APPLY    → Playwright logs in and submits; Craigslist gets direct email
  6. OUTREACH → Gmail SMTP to hiring manager (second channel)
  7. LOG      → JSONL, never re-apply same job

RESUME MODES:
  Honest   — reorder, mirror keywords, strengthen language only
  Enhanced — strategically add skills, fill gaps, embellish for max interviews

TECH STACK:
  Backend:   Python 3.11, FastAPI, APScheduler
  Database:  SQLite
  Scraping:  python-jobspy
  Contact:   DuckDuckGo + DNS MX + SMTP verify (free)
  LLM:       OpenRouter (any OpenAI-compatible)
  Apply:     Playwright
  Email:     Gmail SMTP
  Frontend:  Single index.html (vanilla JS, no build step)
  Deploy:    Railway free tier

COST: ~$0.01/application for LLM. Everything else free.

FILE STRUCTURE:
  backend/
    main.py          — FastAPI + APScheduler + all routes
    database.py      — SQLite (settings, jobs, applications)
    pipeline/
      scrape.py      — multi-platform scraping
      enrich.py      — LLM resume + cover letter
      contacts.py    — free contact finder
      applier.py     — Playwright submit + Craigslist direct
      send.py        — Gmail SMTP outreach
  frontend/
    index.html       — everything: HTML + CSS + JS in one file

API ROUTES:
  GET  /api/settings                → all settings
  PUT  /api/settings                → update (JSON body)
  GET  /api/jobs?limit=50           → scraped jobs
  GET  /api/jobs/new                → unapplied jobs
  GET  /api/applications?limit=100  → history
  GET  /api/applications/stats      → {total_jobs_scraped, sent, failed, pending}
  POST /api/pipeline/run            → full pipeline
  POST /api/pipeline/scrape         → scrape only
  GET/PUT /api/schedule             → {enabled, next_run, hour, minute}
  GET  /api/health
  GET  /api/platforms               → available job platforms

DEPLOY:
  Backend: Railway (push backend/ folder)
  Frontend: served by backend at /app or Vercel
  After deploy: update const API = window.location.origin in index.html

  Run locally:
    cd backend && pip install -r requirements.txt
    uvicorn main:app --reload --port 8000

6. SKILL: HUMANIZER (cover letter anti-AI rules)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Source: skills/creative/humanizer — applied to every LLM-generated cover letter.

THE 10 RULES:
1. No significance inflation: never "stands as a testament," "pivotal moment,"
   "evolving landscape," "vital role." State the fact directly.
2. No -ing endings for fake depth: never "highlighting the importance,"
   "underscoring the need." Say what happened.
3. No promotional language: never "groundbreaking," "innovative," "cutting-edge."
   Be specific instead.
4. No "Not only...but also." Overused LLM construction. State directly.
5. No rule of three. Use 2 or 4, or just one strong point.
6. No copula avoidance: "I am" not "I serve as." "I have" not "I boast a track record of."
7. No filler: never "In order to," "Due to the fact that," "At this point in time,"
   "It is important to note that."
8. No excessive hedging: never "could potentially possibly be argued."
9. No generic conclusions: never "The future looks bright," "Exciting times lie ahead,"
   "I look forward to hearing from you at your earliest convenience."
10. No em dash overuse: max one per paragraph. Use commas or periods instead.

GOOD vs BAD EXAMPLE:
  BAD:  "I am writing to express my strong interest in the PM position at Acme Corp.
         With over 8 years of experience in cross-functional team leadership and a
         proven track record of delivering impactful results..."
  GOOD: "I saw the PM opening at Acme and wanted to reach out. I've spent the last
         8 years running cross-functional projects — most recently at TechCo, where
         I shipped a platform rebuild that cut support tickets by 40%."

VOICE:
  Sentence length: mix short (8w) and medium (15w). Max 25 words per sentence.
  Word choice: "built," "led," "shipped," "fixed" — NOT "spearheaded," "orchestrated"
  Tone: confident not arrogant, specific not bragging, direct not cold
  Structure: Hook → 2-3 achievements mapped to JD → close. No fluff paragraphs.

8. SKILL: WRITING PLANS (task methodology)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Source: skills/software-development/writing-plans

RULES:
  1. Each task = 2-5 min of focused work. If longer, break it down.
  2. Exact file paths. Never "the model file" — say "backend/database.py"
  3. Complete code. Every task has actual code, not a description.
  4. Verification steps. Every task ends with "run X, expect Y."
  5. One action per step. "Write the test" is one step. "Run it" is another.

TASK FORMAT:
  ### Task N: Name
  **Objective:** one sentence
  **Files:** Create/Modify: path/to/file.py
  **Steps:**
  1. Write code
  2. Verify (run X, expect Y)
  3. Commit

PRINCIPLES: DRY, YAGNI, commit after every task (small = easy to revert)

ARCHITECTURE:

  - No .env needed. No API keys in code. Config lives in the web dashboard.
